# How the gallery shows assets (tools/assets.py, book: Assets).  Only for
# viewing: nothing here changes the ROM.
#
# note ASSET TEXT
#   a sentence the gallery prints under that tilemap or level (ASSET: a
#   tilemap path or a level name; Markdown; several note lines for one
#   asset are joined). Only for the reader.
#
# palette PNG PALETTE FIRST
#   the viewing palette of the PNG asset is the colours of the palette
#   asset from FIRST on (2, 16 or 256 of them): `python3 tools/assets.py
#   sync-palettes` copies them into the PNG, `make assets-check` fails
#   when they differ.  Listed where the colours tools/gfx_palettes.py found
#   on screen are those of exactly one palette asset, or where the screen
#   that shows the graphic is known (the row its tilemap gives it, in the
#   palette its palette task copies).  PALETTE level:NAME: the 256 colours
#   of that level preview (its palette=, through EXTBG for extbg=1).
#
# cgram NAME play=PLAY frame=N [skip=I-J,...]
#   the palette of the preview NAME (a level name or a tilemap path) is
#   checked against the emulator (tests/test_previews.py, `make
#   emu-test`): at game frame N of PLAY (a play of tools/c3emu/plays.py;
#   `poweron`: N frames from power-on, no input), the CGRAM holds the
#   colours its palette= gives at every index it sets and every index its
#   pixels show, except the indices of skip= (colours that code or an
#   animation writes there, explained in a note line).  The frames were
#   picked where the screen shows that map and its palette is steady.
# preview TILEMAP chars=ASSET@VRAMWORD,... [base=VRAMWORD] bpp=N palette=PALETTE@INDEX,...
#   the gallery draws the tilemap with the characters of those assets,
#   placed in VRAM where the game's load list puts them (base: the BG's
#   character base; bpp: 2, 4, or 8 for Mode 7), and the colours of those
#   palettes at those CGRAM indices (the palette tasks of the same screen).
